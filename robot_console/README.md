# 智航机器狗任务控制台（开发中）

面向 ZSL-1W / ROS 2 Humble 的 rqt 插件，提供独立窗口入口。默认启动离线演示，不连接机器狗、不自动站立、不发布速度。

## 当前推荐：原 start_all + RViz

rqt 尚未完成，不替代原导航流程。真实设置目标、到点导航和相机仍按上级仓库 README 操作：

```bash
cd ~/robot_ws/robot_sdk_ws
./scripts/start_all.sh
```

使用 RViz 的 **2D Goal Pose** 设置实际目标，相机沿用 `scripts/cam_view.py`。rqt 点位编辑、离线路径预览与真实目标执行尚未打通，真实键盘接管、避障、相机嵌入和变化场景定位恢复仍需开发或验收。完整边界见 [开发状态](docs/DEVELOPMENT_STATUS.md) 和 [原导航说明](../README.md)。

## 首次构建与展示

```bash
cd ~/robot_ws/robot_sdk_ws/robot_console
./build.sh
./start_console.sh --presentation
```

源码在 `package/rqt_robot_console/`；只启动不构建时会回退到独立窗口。`build.sh` 会生成当前路径对应的四个 `.desktop` 快捷方式；移动目录后重新构建，或执行 `/usr/bin/python3 tools/create_launchers.py`。快捷方式不写入系统桌面目录。

## 实验功能：rqt 管理 start_all（2026-11-05）

```bash
./start_console.sh --stack
```

也可双击 `启动系统控制台.desktop`。此入口设置 ROS domain 24 / Zenoh，并直接打开“系统启动”页；**打开窗口不会启动脚本、连接 WebSocket 或发送站立指令**。若检测到已有守护进程，界面显示其状态。

1. 连狗后点击“检查启动条件（只读）”，检查本地依赖及 `192.168.234.1`、`192.168.234.234` 的 ping 连通性。检查不包含授时、定位或姿态确认。
2. 确认场地安全、其他运动任务已停，勾选允许自动站立与守护，点击“一键启动 start_all”。界面再次检查条件，等待现有 WebSocket / ROS 线程退出后，执行所在导航仓库的 `scripts/start_all.sh --boot`。子进程环境固定为 domain 24 / Zenoh，移除离线 localhost 限制和界面的直连配置。
3. 原脚本会清理并重启电脑上的同名导航组件，自动站立、恢复定位，启动地图、自定义导航、RViz、相机，并持续自愈；掉线或定位失败后可能再次站立。脚本运行、独立导航组件残留期间，本界面锁定官方 WebSocket，避免多个 App 客户端争用。
4. 通过“显示 ROS 地图与实时路径”只读查看 `/map`、有效位姿、激光、`/nav_status`、`/custom_nav/path`。路径仅叠加在 ROS map 坐标系地图上；无效坐标、过期时间、错误 frame 被拒绝，停止更新超过 1.5 秒隐藏路径。该话题是原节点输出：原代码无 A* 结果时可能发布到目标的直线，不能仅凭显示曲线判定规划或避障成功。巡航点仍可编辑保存，**此页未把 rqt 巡航点直接发给 custom_nav；真实目标仍从 RViz 下发**。
5. 收工点击“蹲下 → 阻尼”，或守护运行时按 F12。界面通过 pidfd 核验进程身份后向唯一脚本发送 TERM，由其执行禁用运动、lie_down、passive、进程清理。不会把 PID 文件中的任意进程当作目标，不强杀脚本，也不重复打断收工流程。超过 60 秒未退出会显示提示。
6. **关闭 rqt 会保留守护进程。** 重开界面可查看状态、日志和执行收工。务必观察机器狗实际姿态；此操作不是硬件急停。存在无法识别的残留组件时，到原终端处理，界面不会批量强杀。

日志默认在 `/tmp/custom_nav_launch/boot.log`；支持界面滚动查看、打开目录、导出诊断。原 `robot_ws` 脚本和配置未修改。原脚本通过 `grep success` 判断服务结果，可能把 `success=False` 误判为成功，因此本界面仅展示其原始日志，不把“8/8”或脚本退出标成设备/姿态验收成功。原脚本还会重试定位恢复请求、按进程名清理组件，这些行为仍保留；启动前应结束其他运动任务。时间同步仍需按此前验证流程处理。

本次验证使用无 ROS/SSH/网络指令的替身脚本以及本机隔离的 ROS/协议测试；没有执行真实 start_all，没有发送真实站立、导航、蹲下或阻尼指令。

## 先演示这几项

1. 默认展示演示办公室、4 个示例巡航点、模拟机器人及机体系激光。
2. 点击 **开始巡航**，机器人按点位顺序运动；青绿色线为经简化和平滑的模拟 A* 路径，紫色虚线只表示巡航点顺序。可先点击“预览模拟路径”查看完整路线。
3. 点击暂停/继续，按 **F12** 停止。停止后才能编辑路线。
4. 点击 **点选巡航点**，在地图上按下确定位置，拖向目标朝向再松开。普通模式拖动已有点可修改位置；拖空白处平移，滚轮缩放。
5. 直接编辑表格坐标和角度，或上移、下移、删除；保存为 JSON 后可重新加载。路线绑定地图 ID，不能无提示套用到另一张地图。
6. 在“接管与演示”页模拟定位丢失：自动任务先停止，再进入手动待接管。点击键盘区域后按住 W/S 前后移动、A/D 转向，松键/失焦即停；空格停车。
7. 新增模拟障碍可观察重规划或停车。**此模拟器用于界面与流程演示，不是物理仿真，也不代表实机避障验收。**
8. “开始建图—结束建图并等待保存”演示状态变化。要保存真实文件，点击“导出当前地图”，产生 YAML + PGM。

左侧可切换到“已有实机地图（本地）”。它是原工作区地图的复制件，可用于查看和编辑点位；模拟运动只在演示办公室运行。默认 UI 对长控制面板提供滚动条，右侧机体系激光区保持可见。

| 巡航点 | 点选朝向、拖动、表格编辑、排序、保存加载；设备路线读取/新增/修改 | 固件对路线操作的支持与真实执行 |

| ROS 显示 | 只读订阅地图、位姿、激光、定位源、custom_nav 状态；位姿/扫描通过 TF 转到目标坐标系 | Zenoh 路由、实时话题和 TF 是否齐全 |
| 系统启动 | start_all 启停、依赖/连通性检查、进程身份校验、连接互锁、日志、重开识别；ROS 实际路径显示 | 真实整套启动与收工、授时和各节点状态需连狗验收 |
| 键盘接管 | 离线流程、松键/失焦停车、模拟近障保护 | **真实速度发布禁用**；需先部署独占速度仲裁和设备侧超时停车 |

## 连狗后的建议顺序

启动实机通信环境：

```bash
./start_console.sh --robot
# 若只需要 WebSocket + 独立窗口，也可：
./start_console.sh --robot --app
```

实机入口默认 ROS_DOMAIN_ID=24、RMW_IMPLEMENTATION=rmw_zenoh_cpp。可用环境变量 `ROBOT_CONSOLE_DOMAIN_ID`、`ROBOT_CONSOLE_RMW` 覆盖。**`--robot` 会进入实机模式，自动只读连接 WebSocket 和 ROS，读取状态和地图；真实操作权限保持关闭。** ROS 使用本进程配置直连板卡 `192.168.234.1:7447`，无需先启动电脑上的路由器或旧的一键脚本。可用 `ROBOT_CONSOLE_ROUTER` 指定路由器 IP，或用 `ZENOH_SESSION_CONFIG_URI` 提供自己的配置。本程序不启动狗上驱动。

1. 用 `--robot` 启动后自动只读连接。也可从离线窗口手动切换 **实机连接**，检查地址并点击连接；ROS 环境需在启动前设置。
2. 先只读验证定位、建图、导航状态以及地图列表。此时不勾选“允许真实操作”。
3. `--robot` 会自动启动 ROS 只读监测，也可手动启停。位姿源自动兼容实机的 `Header.frame_id` 与旧文档的 `String`；`mc_odom`、无到 map 变换或时间过期的位姿不会显示为有效地图定位。只查看扫描不会启用真实避障。
4. 设备支持后，勾选 **允许真实操作**，逐项测试建图、定位地图加载、路线保存。
5. “当前建图栅格”接口不带地图 ID，本程序将其标记为匿名预览，禁止用它下发路线。有已编辑路线时不会自动替换底图；先保存路线并逐项删除点，或切换到无路线地图再预览。
6. 真实巡航前应停用其他导航/守护脚本，再勾选相应控制权复选框。若 ROS 监测发现 `custom_nav` 状态，会取消官方导航权限。**它无法证明所有其他速度发布源都已停止，复选框也不是底层速度仲裁。**
7. 从设备地图列表选择地图，点击“加载所选地图定位”，等待新鲜的 `ContinuousLoc` 和 `StandBy` 状态，再明确点击开始巡航。
8. **官方连接模式的停止任务/F12 发送厂商 `stop_nav`；start_all 管理模式的 F12 请求脚本收工（蹲下、阻尼）。** 按钮会随模式更名。两者都不替代物理急停。通信中断或关闭界面不能保证狗已停止。使用设备现有遥控器处理真实手动接管。

需要使用旧导航整套链路时，从上述“系统启动”页进入；不要与官方 WebSocket 导航同时运行。检测到 start_all 或独立 custom_nav / ws_map_pub 时，`--robot` 跳过自动 WebSocket 连接。

## 不连狗也能测真实 WebSocket 通道

终端一运行本机模拟设备：

```bash
/usr/bin/python3 tools/mock_device.py
```

终端二启动界面，切换“实机连接”，地址改成 `ws://127.0.0.1:10010`。此时所有消息发给本机模拟器，设备地图 ID 为 `mock_lab`。模拟器只监听 127.0.0.1，不连接机器人。

完整自动集成检查：

```bash
/usr/bin/python3 tools/check_protocol.py
./test.sh
```

协议实现兼容直接 `req_result` 及 `AppResponse`、`AppMapListResponse`、`AppReponseObjectData` 包装，兼容 `loc_load_map → load_localization_map` 响应名称。使用递增帧号和功能名匹配，忽略不相干响应；单个持续连接，串行处理请求，读取请求去重，停止请求优先。操作失败不会自动重发，因为响应丢失不代表设备没执行。

文档对地图数据同时使用“占用栅格”和“字节数组”的说法，默认按现有脚本的 `-1..100` 解码。遇到 255 等值会提示核实编码，**不会把所有灰度值粗暴截断到 100**。确认为 PGM 灰度后可切换编码，当前灰度阈值为空闲 >205、占用 <90、中间未知；真实设备阈值仍需核实。

## 断网测试后带回什么

可以从界面导出诊断 JSON，包含操作日志、状态、地图 ID、路线和 ROS 环境。另有独立只读采集：

```bash
./diagnose.sh                 # 本机依赖和网络配置，不连接机器人
./diagnose.sh --robot         # 增加设备三个状态查询、ROS 节点/话题/服务与消息头
```

输出位于 `runtime/diagnostics/`。该工具不发送建图、定位重置、导航、站立或速度命令。只在没有进行真实导航时运行，并先断开界面 WebSocket，避免与设备单 App 连接限制冲突。实测当前固件会在 App 断开时停止导航，诊断工具的短连接不能与运行中的导航混用。命令均有超时；网络不通时总耗时可能约一分钟。把生成的 JSON 带回即可继续排查。

## 2026-11-02 实机联调结果

本次已连接实机，成功从设备读取地图 `2026_08_08_07_28_38`（682×504，分辨率约 0.05 m，栅格为 -1/0/100）。在真实 rqt 中显示地图、定位位姿和机体系扫描，并验证本地巡航点编辑、保存、回读；测试点未下发给设备。

本轮发现并处理的实际问题：

- NX 与运控板原有 chrony 配置仍指向 `192.168.234.18:1123`，本次电脑为 `.21`。NX 停在 1970 年，算法管理启动脚本因授时未成功循环退出，导致 10010 拒绝连接。经用户明确同意，运行临时电脑授时服务，并在两块板卡的 chrony **运行期**添加 `.21:1123`；没有修改其配置文件。两板同步成功后算法管理自动启动。
- PC 采用进程级 Zenoh 配置直连 `.1:7447`，不需要启动原工作区的整套导航脚本。
- 实机 `/tf_manager/odom_type` 是 `std_msgs/Header`，字段为 `frame_id`。插件现自动识别该类型，并兼容旧版 String；`mc_odom` 不再被当作有效地图定位显示。
- 用户授权站立后，单独启动板卡现有 SDK 驱动，速度输入重映射为 `/console_validation/unused_cmd_vel`，调用 `stand_up_only` 返回成功，速度转发保持关闭。电脑端暂未发现该服务，因此调用发生在板卡本机。
- 仅加载一次旧地图，连续 30 秒查询为 `ContinuousLoc`，位姿源切到 `localization_odom`，map 位姿约 `(0.72,-2.50)`。这确认接口与恢复流程可用，未用外部测量验证定位精度，也不代表变化环境中所有区域均能定位。
- 感知实际处于低功耗状态。按部署文档调用 `data:7` 唤醒，确认 READY=32 后调用 `data:11` 激活，进入 ACTIVE=100。随后收到 `/laser_scan`，frame=`base_link`，每帧 1801 条射线。**扫描显示不等于行走避障验收。**
- 当前固件会在 App WebSocket 断开时请求停止导航。因此界面改为单一持续连接、串行请求，持续读取推送，避免状态查询反复断连。只允许一个 App 客户端，启动界面前应关闭其他连接。真实导航尚未执行。
